# Приглашение в гончарную мастерскую - дизайн

Дата: 03.08.2026

## Что это

Одностраничный сайт-приглашение на свидание. По центру - 3D-сцена: гончарный круг,
на нём вращается кусок глины в форме сердца. Сверху надпись
"Завтра в гончарную мастерскую?", под сценой кнопка "Тык!".

По нажатию кнопки сердце "долепливается" - анимация формовки, - после чего
появляется финальный текст и кнопка, открывающая Telegram с готовым сообщением.

## Решения

| Вопрос | Решение |
|---|---|
| Стек | Один `index.html`, Three.js через CDN (importmap), без сборки |
| Приоритет устройства | Телефон, вертикальный экран; десктоп работает как бонус |
| Стиль 3D | Мультиковый: `MeshToonMaterial`, ступенчатые тени, яркая палитра |
| Реакция на "Тык!" | Формовка сердца → финальный текст → кнопка в Telegram |
| Финальное действие | `https://t.me/ManyLattice?text=Значит%20завтра%20🥰` |

## Экраны

**Экран 1 - приглашение**
- Заголовок: "Завтра в гончарную мастерскую?"
- 3D-сцена по центру
- Кнопка "Тык!"

**Переход - формовка** (~1.8 с, не пропускается)
- Круг ускоряется, глина сжимается и вытягивается вверх
- Сердце становится симметричным и насыщенным по цвету
- Пара "искр" глины разлетается в стороны
- Круг замедляется до спокойного вращения

**Экран 2 - согласие**
- Текст: "Ура! Значит завтра 🥰"
- Кнопка "Написать" → Telegram

3D-сцена живёт непрерывно все три состояния - страница не перезагружается,
меняются только надписи и параметры анимации.

## Архитектура

Один файл, внутри - четыре независимых модуля в теге `<script type="module">`.
Каждый решает одну задачу и не знает о внутренностях остальных.

**`createHeartGeometry()`**
Возвращает `THREE.ExtrudeGeometry`. Форма сердца собирается из кривых Безье
(`THREE.Shape.bezierCurveTo`), экструзия с фаской (`bevelEnabled`) даёт мягкие
округлые края - ключ к "пластилиновому" виду. Чистая функция, без побочных эффектов.

**`createScene(canvas)`**
Собирает сцену: рендерер, камера, освещение (направленный свет + мягкий заполняющий),
гончарный круг (цилиндр + основание), сердце, теневая плоскость.
Возвращает объект с ссылками на то, что анимируется: `{ renderer, scene, camera, wheel, heart }`.

**`createAnimator(sceneRefs)`**
Владеет циклом `requestAnimationFrame` и состоянием сцены.
Публичное API: `start()`, `mold()` (запускает формовку, возвращает Promise),
`dispose()`. Внутри - машина состояний: `idle` → `molding` → `settled`.
Никакого знания о DOM, кроме канваса.

**`createUI(animator)`**
Управляет надписями и кнопками. По клику на "Тык!" блокирует кнопку,
вызывает `animator.mold()`, по завершении промиса показывает финальный экран.
Ничего не знает про Three.js.

Граница между модулями - обычные объекты и промисы. Каждый можно понять,
не читая остальные.

## Детали реализации

**Палитра** (мультиковая, тёплая)
- Фон: мягкий градиент персиковый → кремовый
- Глина: терракотовый `#E8825A`, после формовки насыщается до `#E35D4F`
- Круг: серо-голубой `#8FA3B0`, металлическая ось темнее
- Текст: тёмно-коричневый `#4A2F26`
- Кнопка: заливка глиняного цвета, белый текст, крупный радиус

**Освещение**
Ключевой направленный свет сверху-справа + `HemisphereLight` для мягкого заполнения.
`MeshToonMaterial` со ступенчатой градиентной картой даёт две-три ступени тени -
именно это читается как "мультик", а не как реализм.

**Формовка** - интерполяция трёх параметров по времени с easing:
1. `wheel.rotation.y` - скорость растёт вдвое, потом плавно падает
2. `heart.scale` - приседает по Y, раздаётся по XZ, затем вытягивается обратно
   с лёгким перелётом (эффект отскока)
3. `heart.material.color` - `lerp` от бледного к насыщенному

**Производительность на телефоне**
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))` - без этого на Retina
  рисуется вчетверо больше пикселей, чем нужно
- Тень - не `shadowMap`, а простая тёмная плоскость с прозрачностью под кругом;
  дешевле и лучше вписывается в мультиковый стиль
- Геометрия строится один раз, в кадре только меняются трансформации

## Обработка ошибок

**WebGL недоступен** (старый браузер, отключено ускорение) - `createScene` возвращает
`null`, страница показывает статичный вариант: то же оформление, вместо канваса -
крупная эмодзи-иллюстрация, заголовок и рабочая кнопка. Приглашение остаётся рабочим.

**Prefers-reduced-motion** - сцена рендерится, но без непрерывного вращения;
формовка по клику проигрывается укороченно (0.4 с). Пользователь получает результат,
но не получает крутящийся объект.

**Telegram-ссылка не открылась** - кнопка это обычный `<a href>` с `target="_blank"`;
если приложение не установлено, откроется веб-версия Telegram. Отдельной обработки
не требуется.

## Правки по ходу реализации

Четыре вещи, вскрывшиеся только на живой проверке:

1. **Сердце не вращается вокруг Y.** Экструдированный силуэт при повороте
   встаёт ребром к камере и перестаёт читаться. Крутится только круг,
   сердце покачивается в пределах ±0.22 рад.
2. **Камера считается от размеров сцены.** Первая версия компенсировала только
   узкие экраны - на десктопе круг обрезало. Теперь расстояние берётся как
   максимум из вписывания по высоте и по ширине.
3. **`minmax(0, 1fr)` вместо `1fr`** в grid: иначе канвас раздувается
   и выдавливает кнопку за нижний край экрана.
4. **Кнопка стартует `disabled`** и включается модулем после загрузки Three.js.
   Без этого нажатие на медленной сети пропадало впустую.

## Что сознательно не делаем

- Кнопки "нет" и убегающих элементов - приглашение искреннее, а не игра
- Звука - автоплей на мобильных всё равно блокируется
- Времени и адреса на странице - обсуждаются в переписке
- Сборки, npm, фреймворка - один файл решает задачу целиком
