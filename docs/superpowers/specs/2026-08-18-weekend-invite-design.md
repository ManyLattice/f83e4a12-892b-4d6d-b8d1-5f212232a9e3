# Приглашение на свидание: развилка выходных

Дата: 18.08.2026

## Что это

Одностраничное приглашение для Вики. Страница предлагает два варианта
свидания на ближайшие выходные - пикник или конная прогулка - и даёт
ответить в Telegram.

Третье приглашение в серии (после `ceramic-date` и `moto-date`). Ссылок
на предыдущие нет, страница самостоятельная.

## Задача

Вика знает, что готовятся такие активности - это не сюрприз. Выбор
места и финальное решение остаются за постановщиком; страница нужна,
чтобы получить подтверждение и понять, к какому варианту она склоняется.

Выбор на странице - это её пожелание, а не финальное решение. Погода на
выходных может быть дождливая, и последнее слово всё равно за
постановщиком.

## Механика

Один экран, без скролла. Два состояния.

### Состояние 1: развилка

- Две половины на весь viewport, каждая - только иллюстрация
- Никакого текста на половинах: ни названий активностей, ни описаний
- Поверх, сверху по центру - заголовок «Вика, эти выходные»
- Обе половины равноценны, ничто не выделено заранее

### Состояние 2: выбрано

- Тап по половине - она раскрывается на весь экран, вторая уходит
- Заголовок меняется на подтверждающий
- Снизу появляется кнопка «Написать»
- Кнопка открывает Telegram с заготовленным текстом

### Передумать нельзя

Обратного пути в интерфейсе нет. Захочет посмотреть второй вариант -
обновит страницу. Это осознанное решение: кнопка «назад» превратила бы
выбор в перебор опций, а он должен быть импульсом.

## Как иллюстрации читаются как кнопки

Текста-подсказки на странице нет, поэтому кликабельность передаётся
только поведением:

- Половины медленно «дышат» - едва заметный зум иллюстраций, разнесённый
  по фазе между половинами, чтобы они жили не в такт
- Тач: половина проседает под пальцем (scale 0.98)
- Десктоп: наведение осветляет половину и приглушает вторую
- В покое обе половины слегка притемнены - выбор «зажигает» одну

Курсор на десктопе - `pointer`. Половины размечены как `<button>`, а не
`<div>`, чтобы работали с клавиатуры и в screen reader.

## Переход

1. Выбранная половина едет к 100% ширины (на мобильном - к 100% высоты)
2. Вторая ужимается до нуля и уходит
3. Заголовок меняется
4. После завершения раскрытия - появляется кнопка

Длительность ~600-700 мс, плавное замедление. Кнопка появляется с
задержкой после раскрытия, а не одновременно с ним: движение должно
читаться как одно действие.

При `prefers-reduced-motion` анимации выключаются, состояния меняются
мгновенно.

## Адаптив

Основной сценарий - мобильный: она откроет ссылку из Telegram.

| | Развилка | После выбора |
|---|---|---|
| Мобильный | Половины друг под другом, каждая 50vh | Выбранная 100vh |
| Десктоп | Половины рядом, каждая 50vw | Выбранная 100vw |

## Тексты

Всё содержимое страницы:

| Место | Текст |
|---|---|
| Заголовок вкладки | Вика, эти выходные |
| Заголовок на развилке | Вика, эти выходные |
| После выбора пикника | Значит, пикник |
| После выбора лошадей | Значит, лошади |
| Кнопка | Написать |
| Сообщение в Telegram (пикник) | Давай пикник |
| Сообщение в Telegram (лошади) | Давай лошадей |
| og:description | Выбирай |

Тексты живут в блоке `CONFIG` в начале скрипта - как в `moto-date`.
Поменять формулировку можно в одном месте, не трогая разметку.

## Telegram

Кнопка открывает `t.me/ManyLattice` с текстом, подставленным в поле
ввода. Сообщение не отправляется автоматически - нажать send остаётся
её решением.

## Ассеты

Две иллюстрации, сгенерированы и уложены в `images/`.
Оригиналы PNG лежат в `.orig-art/` вне git.

| | Пикник | Лошади |
|---|---|---|
| Файл | `images/picnic.webp` | `images/horses.webp` |
| Формат | WebP, 1086×1448 | WebP, 1086×1448 |
| Палитра | Тёплая зелень, солнце сквозь листву | Охра степи, пыль, тёплый горизонт |
| Сюжет | Плед на траве, корзина, фрукты | Лошадь в степи, силуэт на фоне неба |

### Требования к кадру

Оба изображения показываются в двух разных пропорциях - узкой на
развилке и широкой после раскрытия. Отсюда два ограничения:

1. **Сюжет по центру, с запасом по краям.** Центральный объект должен
   пережить оба кадрирования (`object-fit: cover` режет по-разному).
2. **Верхние ~20% спокойные.** Там лежит заголовок - нужна ровная
   область без мелких деталей и резких контрастов.

### Фактическая композиция и кадрирование

Сгенерированные иллюстрации красивые, но сюжет в обеих смещён от
геометрического центра:

- **Пикник** - корзина примерно по центру по горизонтали, но вся сцена
  живёт в нижних двух третях; верхняя треть это фон из листвы и неба.
- **Лошадь** - сдвинута левее центра, стоит примерно на 45% высоты;
  снизу заметный запас сухой травы.

Перегенерировать ради формальной центровки не стали - вместо этого
точка фокуса задаётся в CSS через `object-position`, своя для каждой
иллюстрации и для каждого состояния (узкий кадр на развилке, широкий
после раскрытия). Значения подбираются на реальных экранах так, чтобы
корзина и лошадь оставались в кадре в обеих пропорциях.

Поверх обеих иллюстраций лежит общий тёмный оверлей: он держит
читаемость белого заголовка независимо от того, что на картинке.

## Технические решения

- Один файл `index.html`, стили и скрипт inline
- Без сборки, без зависимостей - как оба предыдущих проекта
- Хостинг GitHub Pages
- `og:image` - абсолютный URL (Telegram игнорирует относительные пути)
- `theme-color` подобран под палитру, чтобы chrome встроенного браузера
  Telegram не давал светлых полос сверху и снизу
- Без JS страница остаётся в состоянии развилки: обе иллюстрации видны,
  выбор не работает. Деградация мягкая, а не белый экран.

## Что намеренно не делается

- **Нет отправки выбора на сервер.** Ответ приходит в Telegram живым
  сообщением. Страница остаётся одним файлом без бэкенда.
- **Нет деталей свидания на странице** - ни времени, ни места, ни что
  надеть. Место ещё не выбрано, и выбирает его постановщик.
- **Нет плана Б на случай дождя.** Погода решается вживую, страница про
  настроение и подтверждение.

Копируются в генератор как есть. Оба кадра вертикальные, сюжет по

### Если кадр не подошёл

Чаще всего ломается одно из двух:

- **Сюжет уехал от центра** - при раскрытии половины объект срежется.
  Добавить в промпт `subject strictly centred, wide margins on every side`.
- **Верх забит деталями** - заголовок станет нечитаемым. Усилить:
  `the upper 20% must be empty sky with no detail`.
